# 钉板（Pinboard）

## 目标

读者可以把**结果**（定理/引理/定义…）、**行间公式**、**图**钉到一个侧栏里，读别处时不用来回滚动；钉板还能一键把内容
（TeX 源码 + Markdown）连同"我卡在哪里"复制到剪贴板，粘贴给 AI。

界面要尽量简单：平时页面上不多任何东西，钉板为空时完全不显示。站点界面是英文，所有 UI 文字用英文。

## 4. `pinboard-core.js`（纯函数，全部 `export`）

### `splitMacroDefs(src: string): {name: string, text: string}[]`

把宏文件切成顶层定义，逻辑和 `src/latex.ts` 的 `buildMacros` 分块一致：逐行去掉 `%` 注释（`\%` 不算），
按花括号平衡切块（`\\` 后一个字符跳过）。每块的 `text` 是**原始文本**（保留注释前的原样，去掉首尾空白），
`name` 是被定义的命令名（含反斜杠），识别：

- `\newcommand` / `\renewcommand` / `\providecommand`，可带 `*`，名字可带或不带花括号：`\newcommand{\Q}…`、`\newcommand\Q…`
- `\def\name` / `\gdef\name`
- `\DeclareMathOperator` / `\DeclareMathOperator*`，名字可带或不带花括号

识别不出名字的块丢掉。

### `macrosUsed(text: string, defs): {name, text}[]`

返回 `text` 用到的定义，**传递闭包**（定义体里又用到的宏也要带上），按 `defs` 原顺序。"用到 `\Q`"指出现
`\Q` 且后面不是字母（`\Qbar` 不算用到 `\Q`）。

### `buildPrompt({ bookTitle, items, question, macroDefs }): string`

`items` 每项 `{ label: string, url: string, text: string }`（`url` 为绝对地址）。输出（`question` 去空白后为空
则省略最后一节；用到的宏为空则省略宏那一节；宏由 `macrosUsed(所有 item.text 拼起来 + question, macroDefs)` 求出）：

````
I'm reading "<bookTitle>". Below are the parts I pinned; math is in LaTeX.

Macros used:
```latex
<每个定义的 text，一行一个>
```

## <item.label>
Source: <item.url>

<item.text>

## Where I'm stuck
<question>
````

各节之间一个空行，结尾一个换行，不出现连续两个以上的空行。

## 5. `pinboard.js`（DOM）

开头：`const core = await import("./pinboard-core.js" + new URL(import.meta.url).search);`
（让 core 跟 `?v=` 一起失效缓存）。

### 存储

localStorage 键 `pinboard:v1`，值 `{ open: boolean, question: string, items: Item[] }`，读失败/格式不对当空板。

```
Item = {
  key: string,        // 去重/切换用，见下
  kind: "result" | "formula" | "figure",
  tag: string | null, // 最近的祖先 article.result[data-tag] 的 tag
  labelHtml: string,  // 卡片标题（HTML，可含 KaTeX）
  label: string,      // 同一标题的 Markdown 文本（给 AI）
  href: string,       // tag ? "/tag/" + tag : location.pathname
  html: string,       // 卡片内容快照
  text: string,       // 内容的 Markdown（给 AI），钉的时候就算好
}
```

`key`：结果 `r:<tag>`；公式 `f:<tag 或 location.pathname>:<公式 TeX>`；图 `g:<img src>`。

监听 `storage` 事件，别的标签页改了就重新渲染。写入超出配额时 `alert("The pinboard is full. Remove some pins first.")`，不改状态。

### 钉按钮

在 `main` 里给这三类目标加按钮（不处理钉板内部的元素）：

| 目标 | 按钮放哪 |
|---|---|
| `article.result[data-tag]` | 追加到它自己的 `.result-head` 末尾（`.tag-link` 之后） |
| `.math-display`（只限内部有 `.katex-display` 的） | 先用 `<div class="pin-host">` 包住它，按钮绝对定位在 pin-host 右上角（不能放进会横向滚动的 `.math-display` 里） |
| `figure.tex-figure` | 给 figure 加 `pin-host` 类，按钮绝对定位在右上角 |

按钮：`<button type="button" class="pin-btn" aria-pressed="false" aria-label="Pin" title="Pin">` + 内联 SVG 图钉
（`fill="currentColor"`，约 1em）。已钉时 `aria-pressed="true"`、`aria-label`/`title` 为 `"Unpin"`。点一下钉，再点取消。
每次状态变化后同步页面上所有按钮的 `aria-pressed`。

页面加载时扫一次；用 `MutationObserver`（像 `proofparts.js` 那样用 `requestAnimationFrame` 合并）处理后来插入的
knowl 内容。已处理的元素打标记，别重复加。

### 钉的时候生成什么

公共步骤：`clone = el.cloneNode(true)`，然后在 clone 里删掉 `.pin-btn`、`.knowl-box`、`.part-picker`、`.qed`，
把 `.proof-part` 拆掉（子节点移出来）、去掉所有 `hidden` 属性和 `id` 属性，把 `.pin-host` 包装拆掉。

- **结果**：
  - `labelHtml` = `.result-head` 里 `.result-label` 和 `.result-title` 的 HTML（中间一个空格）；`label` 同理用 `toMarkdown`。
  - 内容 = `.statement`，加上**钉的时候页面上看得见的证明**：`details.proof[open]` 或 `section.proof`（结果页上证明总是展开）。
  - `html`：陈述的 HTML；每个带上的证明放进卡片里一个**默认收起**的 `<details class="pin-proof"><summary>Proof</summary>…证明体…</details>`
    （多个证明时 summary 用原来的 "Proof 1"/"Proof 2"）。
  - `text`：陈述的 Markdown；每个证明接在后面，前面一行 `*Proof.*`（或 `*Proof 1.*`）。
- **公式**：`text` = `$$\n<TeX>\n$$`；`html` = 那个 `.math-display` 的 HTML。
- **图**：`text` = `[Figure: <alt>](<img 的绝对 URL>)`；`html` = figure 的 HTML。
- 公式/图的标题：在证明里（祖先 `.proof`）→ `Formula in the proof of <结果标签>`；在陈述里 → `Formula in <结果标签>`；
  不在任何结果里 → `Formula in <页面 h1 的文字，去掉 .tag-link>`。图把 `Formula` 换成 `Figure`。结果标签只用
  `.result-label`（不带标题）。

### `toMarkdown(node)`（DOM → Markdown，写在 `pinboard.js` 里）

- `.katex-display` → 单独成段的 `$$\n<TeX>\n$$`；不在 `.katex-display` 里的 `.katex` → `$<TeX>$`。
  TeX 取 `annotation[encoding="application/x-tex"]` 的 `textContent`。
- `.math-error`（KaTeX 渲染失败时显示原 TeX）→ 同上规则用它的文字包 `$`/`$$`（有 `display` 类用 `$$`）。
- 链接 → 只要文字（递归转换）。
- `p`、`div`、`blockquote`、`figure` 等块 → 前后空行；`ul`/`ol` 的 `li` → `- ` / `1. `、`2. `…；`li.labeled` → `- (i) 内容`；
  `dt`/`dd` → `- dt: dd`；`br` → 换行。
- `em`/`i` → `*…*`，`strong`/`b` → `**…**`。
- `img` → `[Figure: alt](绝对 URL)`。
- 跳过 `button`、`.pin-btn`、`.knowl-box`、`.part-picker`、`.qed`。
- 文本节点里的空白压成一个空格；最后修剪每行首尾空白，3 个以上连续换行压成 2 个。

### 钉板 UI

`<aside class="pinboard" aria-label="Pinboard">` 加到 `body` 末尾，另有一个收起时显示的
`<button class="pin-tab">` 图钉 + 数量。

- 空板：两者都隐藏，`body` 不加类。
- 非空且 `open`：显示钉板，`body.pinboard-open`；非空且收起：只显示 `pin-tab`（右下角固定的圆角小按钮），点它展开。
- 钉板结构：
  - 头部：`Pinned (n)`，右边一个 `Hide` 按钮（收起）。
  - 中间（可滚动）：卡片列表，按钉的先后顺序。每张卡片 = 头部（`labelHtml` 做成链接 + 右边 `×` 删除按钮）+ 内容（`html`）。
  - 底部（不随卡片滚动）：`<textarea placeholder="Where I'm stuck…">`（2 行，随内容长高到约 6 行，内容实时存进 `question`）
    + `Copy for AI` 按钮 + `Clear` 按钮。
- 点卡片标题：若当前页 `document.getElementById(tag)` 存在 → `scrollIntoView({behavior:"smooth", block:"start"})`
  并给它加一次 `knowl-flash` 类（先移除、强制重排、再加，同 `knowl.js`）；否则跳到 `href`。
- `Clear`：`confirm("Remove all pins?")` 后清空 items（保留 question）。
- `Copy for AI`：`fetch("/api/macros")`（失败就当没有宏），`buildPrompt({ bookTitle: .site-title 的文字, items 映射成
  {label, url: location.origin + href, text}, question, macroDefs: splitMacroDefs(宏源) })`，
  `navigator.clipboard.writeText`。成功则按钮文字变 `Copied ✓` 1.5 秒；失败则在底部显示一个只读 textarea 放这段文字、
  全选，并提示 `Press Ctrl+C to copy.`
- 卡片里的 `a.ref` 照常由 `knowl.js` 展开（它用 document 级事件委托，不用做什么）。
- 新钉一项时自动 `open = true`。

### CSS（追加到 `style.css`）

用现有变量（`--bg`、`--fg`、`--muted`、`--accent`、`--accent-soft`、`--border`、`--knowl-bg`），自动支持深色模式。
钉板和按钮用 `system-ui` 字体，卡片内容字号约 0.9em。

- `.pin-btn`：无边框透明背景，`color: var(--muted)`，`opacity: 0`；宿主 `:hover`/`:focus-within` 时 `opacity: 1`；
  `aria-pressed="true"` 时常驻显示且 `color: var(--accent)`；`@media (hover: none)` 下常驻 `opacity: 0.5`。
  结果的按钮在 `article.result:hover > .result-head` 时显示。`.pin-host { position: relative; }`，公式/图的按钮
  `position: absolute; top: 0; right: 0`。
- **宽屏 `@media (min-width: 72rem)`**：钉板 `position: fixed; top: 0.75rem; right: 0.75rem; bottom: 0.75rem; width: 20rem`，
  `body.pinboard-open { padding-right: 21.5rem; }`（正文在剩余空间里居中）。
- **窄屏**：钉板 `position: fixed; left: 0; right: 0; bottom: 0; height: 40vh`，上边框和阴影；
  `body.pinboard-open { padding-bottom: 40vh; }`。
- 钉板内部：flex 纵向，头部/底部固定，卡片区 `overflow-y: auto`；卡片里 `.math-display` 横向滚动，`img { max-width: 100% }`。
- `@media print`：隐藏 `.pinboard`、`.pin-tab`、`.pin-btn`。

### 返工 2（GPT 审查 + 真实内容截图后发现的问题）

工作区里 `src/views/layout.ts` 的 `ASSET_VERSION = "6"` 是主会话有意改的、还没提交，**保留它，不要改回**。
只改 `public/static/pinboard.js`、`public/static/pinboard-core.js`、`public/static/style.css`、
`test/pinboard-core.test.ts`。不要 commit。

1. **别的标签页一改，卡片就整体重画**（`render`）。现在只要 `items` 数组引用变了就 `replaceChildren`，所以另一个标签页
   打一个字（`storage` 事件 → 重新 `JSON.parse`）就会把这一页卡片里展开的 knowl/证明全部收起。改成：只有卡片内容真的变了
   才重画——按 `item.key` 复用已有的卡片节点，只新增/删除/调整顺序；`key` 相同但 `html`/`labelHtml` 变了的才替换那一张。
   按钮 `aria-pressed` 的同步保持不变。
2. **宏：一行里有多个定义时只认出第一个**（`splitMacroDefs`）。例如 `\newcommand{\A}{a}\newcommand{\B}{b}` 写在同一行，
   服务端两个都能用，但导出只认出 `\A`。在现有的花括号平衡切块之后，再在**花括号深度 0** 处遇到下一个定义命令
   （`\newcommand`、`\renewcommand`、`\providecommand`（可带 `*`）、`\def`、`\gdef`、`\DeclareMathOperator`（可带 `*`））时切开，
   每段各自得到 `name` 和 `text`。
3. **宏：TeX 注释误报**（`macrosUsed`）。扫描"用到哪些宏"之前，先去掉未转义的 `%` 到行尾（`\%` 不算注释），
   对正文和定义体都这样做。
4. **嵌套列表导出后被压平**（`toMarkdown` 的 `UL`/`OL`）。`li` 里的子列表和续段要缩进到列表标记的宽度
   （`- ` 缩进 2 格，`1. ` 缩进 3 格，多位数按实际宽度），这样读者能看出续段属于哪一项。最后"修剪每行首尾空白"那一步不能把这些
   缩进删掉——只去行尾空白，行首缩进保留（顶层文字本来就没有行首空白）。
5. **公式里含 `$` 时分隔符冲突**（`toMarkdown` 和公式卡片的 `text`）。TeX 里含 `$` 时：行内用 `\(`…`\)`，行间用
   `\[`…`\]`（各占一行，格式同 `$$`）；不含 `$` 时保持现在的 `$…$` / `$$…$$`。
6. **宽公式在卡片里被截断**。卡片渲染后、钉板从隐藏变为显示时、以及窗口 `resize` 时，对卡片里每个 `.katex-display`：
   先清掉之前设的字号，若 `scrollWidth > clientWidth`，把它的 `style.fontSize` 设成 `max(0.6, clientWidth / scrollWidth)` 的百分比，
   缩到 60% 还放不下的就保持横向滚动。钉板隐藏时不量（量不出宽度）。不要用 `requestAnimationFrame`（后台页面里不触发），直接调用即可。
7. **手机上问题框把卡片区挤没了**。窄屏布局（`max-width: 72rem` 以下，也就是底部抽屉）里，问题框最多长到约 3 行，再多就在框内滚动；
   宽屏仍是约 6 行。用 CSS `max-height` + `overflow-y: auto` 实现，`resizeQuestion` 的自动长高要尊重这个上限。
8. **窄屏抽屉挡住跳转目标**。窄屏且钉板打开时，让 `scrollIntoView`/锚点跳转避开底部抽屉：
   `html:has(body.pinboard-open) { scroll-padding-bottom: 40vh; }`（只在窄屏媒体查询里）。

**测试**（`test/pinboard-core.test.ts` 追加）：同一行两个定义都被认出且按原顺序；`\B` 的定义体里只在 `%` 注释中出现 `\A` 时，
`macrosUsed` 不带上 `\A`；正文里 `\%` 后面的宏仍算用到。
